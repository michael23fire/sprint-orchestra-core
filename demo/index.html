Sprint Orchestra — RAG / Agentic AI / GenAI demo

Talks directly to ai-service (agentic corrective-RAG) and vectorization-service (hybrid retrieval) over HTTP. No backend of its own — this is a static page, open it directly or serve it with python -m http.server from this folder.

Connection
1. Ask — agentic corrective-RAG (POST /ask)
Grounded — should answer confidently, with citations (ATC-*) Abstention — not in this dataset, should honestly say so Corrective retrieval — vague phrasing, watch queries_used reformulate Sprint reasoning / why — carry-over, blockers, multi-hop Cache demo — ask the exact same question again right after any of the above
2. Search — hybrid retrieval (POST /search)
Try the same query in all 3 modes to see hybrid's value Exact identifiers — where lexical wins and vector structurally can't
3. AI-assisted task creation (POST /draft-task)

One structured-output call (Instructor + Pydantic, Jinja2-templated prompt) turns a rough description into a title/labels/estimate/dependencies draft. Never blocks task creation — if the model fails, you still get a usable fallback draft (watch for the degraded badge).

Try these — real-flavored descriptions, not synthetic test strings
4. Plan Epic with AI — durable review and publish (POST /plan-epic/rollout)

Generates a complete epic plan, pauses for human review in a Postgres-checkpointed LangGraph workflow, then publishes the approved epic, sprint buckets, child issues, and dependencies from the server. Needs a real user id/username because jira-backend attributes created work to a real reporter.

Try one of these

To see durable resume for real (not simulated in this page): generate a plan, click Approve, and — in a terminal, while it's mid-commit — kill and immediately restart the ai-service process. Click "Refresh status" and then "Resume publishing" once it's back up; the workflow continues from its last recorded checkpoint instead of relying on browser memory.
