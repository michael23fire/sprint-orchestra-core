Entity–relationship diagram (visual)

Complete view of the current Flyway V1–V26 schema: 17 application tables, 146 columns (including generated search_vector columns), and 30 foreign-key relationships. Each entity includes every persisted column; nullable and default values are noted inline. Nullable relationships include spaces.owner_id, issues.sprint_id / parent_id / assignee_id / reporter_id, labels.deleted_at, issue_history.actor_id, issue_attachments.uploader_id, issue_code_links.creator_id, and sprint metric columns on sprints. Junction tables implement logical many-to-many between users, spaces, groups, issues, and labels. See DATABASE_SCHEMA_CORE.md for migration history and index details. Mermaid loads from jsDelivr (network once unless cached).

Unique keys: users(username), users(email), issues(issue_key), labels(space_id, normalized_name), sprint_issue_history(sprint_id, issue_id), and issue_attachments(storage_filename). Partial unique indexes apply to non-null users.google_sub, non-null users.github_id, and active spaces.space_key (deleted_at IS NULL). Composite unique keys are shown in entity comments for memberships, space/group and repository links, issue links, and issue code links.
